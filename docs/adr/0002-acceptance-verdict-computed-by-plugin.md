# 验收判定由插件计算，主对话不再自判

## 背景

今天 `manager_verify` 的 `pass` / `fail` 是主对话传进来的结论。插件确实在核对，但核对的是**形状**：记录读得懂、阶段对、验收标准指纹没被改、该部分最近一条是 `done`、证据非空、`verdict` 是个枚举值。这套校验保证「话的形状对」，不保证「话是真的」。在长项目里，这正是**假完成**最廉价的入口：主对话把自己的判断写成 `pass`，一路都合规。

## 决定

每条**验收标准**绑定一个**检查**。检查由插件执行，判定由检查结果算出。主对话只能请求执行检查、提交原始输出，**不能提交结论**。

**判断型标准**（界面外观、措辞）没有检查，不参与机械验收，永远走**待确认**，由用户裁决 —— 沿用 ADR-0001 已确立的第三把钥匙。

`Verification` 的含义因此改变：从「主对话拿证据对照标准」变成「插件按检查计算」。项目层面的完成仍只归用户 —— ADR-0001 的这一半原样成立；它「边界」一节里「部分层面的验收由主对话执行」那半句，被这份 ADR 取代。

## 考虑过的选项

- **独立复核子对话**：另起一个模型来判定。否决 —— 客观性来自「代码算」，不来自「另一个模型算」；那只是把同一个失效模式换了个位置。
- **只复现证据，判定仍归主对话**：插件复跑命令、重算指纹，但 pass/fail 还是模型给。否决 —— 判定留在模型手里时，复现出的证据只是参考材料，模型可以在证据不利时照判通过。
- **硬证据卡死一切**：ADR-0001 已经否决过 —— 界面、文档类标准会被永久卡住。

## 后果

- 验收标准在项目启动时就必须写成「带检查」的条目，自由文本不再够用；已有项目需要迁移。
- 「连续两次同样的失败」不再比较模型写的理由文本，改为比较**未通过的检查集合** —— 改措辞不再能绕过。
- 驳回原因可以回灌下一次派分：子对话重试时知道自己要补哪条检查。
- 插件必须有一条受控的命令执行通道（已有），以及把检查失败结构化落盘的记录格式。
