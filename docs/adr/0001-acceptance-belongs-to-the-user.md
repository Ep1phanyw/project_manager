# 验收权归用户，主对话不得自我宣布达标

## 背景

这个插件让一个**主对话**规划项目、把**部分**分派给**子对话**、循环推进到交付完成。一旦允许主对话自己判断「达标了」，系统就会在某个时刻自我满足然后停下 —— 而这是用户最难发现、也最不能接受的失败模式：它停下时的样子，和真正完成一模一样。

## 决定

**验收标准**由用户设定，且只能由用户设定。主对话负责对照验收标准逐条核对，并为每一条提供可复现的**证据**；它没有权力宣布项目完成、降低验收标准、或把自己判定为**阻塞**。

主对话能合法停下的出口只有三种：同一部分连续两次验收失败且失败原因未变、缺少只有用户能提供的东西、需要改动验收标准本身。除此之外它必须继续换方案。

## 考虑过的选项

- **主对话自行判断达标**：最省事，自主性最强，但会把「假完成」变成默认行为。否决。
- **允许主对话在困难时降低验收标准**：标准会随时间漂移，用户永远不知道该拦哪一次。否决。
- **硬证据卡死一切**：对代码部分成立，但文档、界面外观这类部分跑不出测试，会被永久卡住。改为引入 `needs user verification` 作为一个独立的暂停状态，而不是把「我确认过了」算成证据。

## 后果

- 用户成为整条回路里唯一的验收权威，这限制了一部分无人值守能力 —— 是有意付出的代价。
- 每条验收标准都要求可复现的证据，所以**计划**在批准时就得写清每部分的证据类型，不能事后补。
- 「阻塞」永远是一个需要用户裁决的事件，不是一个模型可以自行消化的状态。
