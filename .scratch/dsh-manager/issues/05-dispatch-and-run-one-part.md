## 验证记录

- **实机跑通了**：`smoke-05` 项目经用户批准后调用 `manager_run`，真的起了一个子对话。它列了工作区根目录、把 PowerShell 命令输出当证据、回报 `done`，插件把它记成了 P1 的完成记录。
- **子对话隔离**：用 `provider: 'spawn'`，不继承父会话上下文 —— 这正是「只做这一部分、只回结果」的实现方式。
- **回报靠 schema**：`manager_run` 请求 `outputSchema`，`SubagentResult.structured` 直接给出校验过的对象；不从自由文本里解析 JSON。
- **任务描述**：`buildPrompt` 把部分编号、标题、文件集、证据类型、项目目标与验收标准一起交给子对话。
- **失败隔离**：子对话报错、抛异常、回报不合规，都记为可重试记录，项目继续可用。轮次按部分累加，历史不丢。

## 实机暴露的 bug（已修）

第一次真实回报就把它打出来了：**子对话的多行命令输出会把 `parts.md` 写成读不回来的样子**（内容行没有缩进，解析器把它们当成结构行）。更严重的是子对话可以在摘要里写 `## [P2] 第 1 次 · … - 状态：done` **伪造另一个部分的完成记录**。

修法：结构行只在**顶格**时识别，子对话给的文本一律缩进写入。这样内容既写不坏文件，也伪造不了记录。八个往返测试覆盖：多行摘要、多行证据、证据里带字段行、摘要里伪造标题、多行阻塞原因、真实回报形状。

## 已知的桥（属于 06 / 07，现在先记下）

- **`done` 直接放行依赖**：这是子对话的自报，主对话还没有按验收标准核对 —— spec 明确「模型不能直接写完成」，票 06 会把验收插到「子对话说完成」和「项目认完成」之间。
- **任何非空理由的 `blocked` 都会停下整个项目**：ADR-0001 要求阻塞只在三种情形成立，这条闸门目前只在提示词里，票 07 要把它挪到返回值上。

## 关于「完整记录」

子对话的完整会话记录由 DSH 自己持久化（`$DSH_HOME/sessions/` 下按工作区与会话 id 存放），插件在 `parts.md` 里记下 `- 子会话：<id>` 作为索引。插件**不复制**一遍 transcript —— 复制只会让两份记录各自漂移。
