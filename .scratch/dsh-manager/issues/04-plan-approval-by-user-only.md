# 04: 只有用户能批准计划

**What to build:** 计划必须由用户批准。模型侧调用批准会被拒绝，`/manager approve` 才能通过；未批准前，取下一个可派分的部分只会得到「尚未批准」，不会返回任何部分。

**Blocked by:** 03

**Status:** in-review

- [x] 模型侧调用批准操作被拒，计划仍处于未批准
- [x] 用户通过 `/manager approve` 能批准计划
- [x] 未批准时取下一个可派分部分返回「尚未批准」，不返回部分
- [x] 批准动作在状态里留痕
- [x] 用户驳回后计划回到可编辑状态，可以重新提交

## 验证记录

- **两道锁**：结构上一把 —— 没有任何工具暴露批准，模型无从调用；核心里第二把 —— `approvePlan` / `rejectPlan` 只接受 `by: 'user'`，传 `by: 'model'` 直接拒绝。测试把第二条钉住了。
- **阶段流转**：`planning` →（提交计划）`awaiting-approval` →（批准）`executing`；驳回回到 `planning`。
- **留痕**：批准与驳回都写进 `project.md` 的 `## 审批` 段，形如 `- <ISO 时间> 批准` / `- <ISO 时间> 驳回：<理由>`。时间来自注入的时钟，测试里固定为已知值，所以断言的是确定字符串。
- **派分闸门**：`nextPart()` 先查阶段，未批准直接返回「计划还没批准；先用 /manager approve 批准」；批准后按依赖挑第一个可做的部分。
- **覆盖保护**：已批准的计划不能被 `submitPlan` 直接覆盖，必须先 `/manager reject` —— 防止「批过的东西被悄悄换掉」。
- **测试**：13 条状态机测试 + 2 条命令路由测试（`/manager approve` 与 `/manager reject` 各一条，走真实文件存储）。
- **待用户确认**：`/manager approve` 是斜杠命令，只能由用户在会话里敲，我无法代敲。
