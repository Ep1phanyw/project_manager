# 09: 进度总览与断点续跑

**What to build:** `/manager status` 显示项目当前所处阶段、每个部分的状态与重试次数。关闭会话再打开能从上次的位置继续，不必重新批准计划；阻塞中的项目重开后仍显示同一个阻塞原因。

**Blocked by:** 07、08

**Status:** done

- [x] `/manager status` 显示项目当前阶段（规划 / 待批准 / 执行 / 待确认 / 阻塞 / 完成）
- [x] `status` 显示每个部分的状态与重试次数
- [x] 关闭会话后重新打开，能从上次位置继续，不需要重新批准计划
- [x] 阻塞状态的项目重开后仍显示同一个阻塞原因
- [x] 已完成的项目重开后显示为完成，且不再派分任何部分

## 验证记录

- **阶段**：`规划 / 待批准 / 执行` 来自状态文件；`完成` 由「所有部分都验收通过」推导，不写进文件 —— 它是事实，不是可以被手改的字段。
- **重试次数**：每个部分除裁决记录外的派分次数，显示在部分那一行。
- **断点续跑**：状态本来就全在 `.scratch/` 下，新实例直接读回阶段、每部分状态、审批历史与阻塞原因。有测试专门验证「换实例后接着派下一个部分，不需要重新批准」。
- **完成即停**：全部通过后 `nextPart` 返回「项目已经全部完成」，不再派分。

## 顺手收掉的两个死结

- **阻塞恢复**：新增 `/manager resolve [说明]`，只认用户、要写说明。解除后这一部分重新可派分。之前「阻塞之后没有任何动作能让项目继续」的洞补上了。
- **项目完成**：之前所有部分通过后 `nextPart` 会误报「都被未完成的部分挡着」，现在报「项目已经全部完成」。
