# 03: 计划提交与校验

## 验证记录

- **入口**：`manager_plan` 工具（模型调用）；`/manager` / `/manager status` 展示计划。
- **落盘格式**：`.scratch/<项目>/plan.md`，每个部分一个 `## [Pn] 标题` 块，下面 `- 依赖：`（每行一个，或「无」）、`- 证据：` 一行、`- 文件：`（每行一个）。一个文件一行、一个依赖一行，所以路径里带逗号也不会被拆开；解析按行锚定，认不出的行会被报出来。
- **校验规则**：编号合法且唯一；每部分必须有标题、文件集、证据类型；依赖必须指向计划内的部分；依赖不得成环（DFS 找环并回报环上路径）；文件集重叠的两个部分必须在依赖图上**有先后关系**。
- **关于「依赖边」**：判定用的是可达性而非直接边 —— `P1 → P2 → P3` 时 P1 与 P3 共享文件是安全的，因为没有直接边却要求它们有直接边会误杀正确计划。
- **路径归一**：`./src/x.js` 与 `src/x.js`、`src\x.js` 视为同一文件。
- **拒绝不落盘**：校验失败的提交不会写任何东西，原有计划与项目状态保持不变。
- **证据类型**：只接受 `test` / `build` / `command` / `artifact`，拒绝时把允许值列出来。
- **测试**：14 条新测试，覆盖上述每种拒绝与两种放行；其中一条走真实文件存储并跨实例读回。
- **实机**：重载插件后依次调用 `manager_start` 与 `manager_plan`，`plan.md` 内容与提交一致；再提交一个文件集重叠的计划，工具真的返回错误 `部分 P1 与 P2 都改 src/shared.js，却没有先后关系（P1 → P2 或 P2 → P1）`，而不是静默接受。验证产物已清理。

## 评审后的修正

两轴评审各抓到一类问题，已改：

- **部分标题带换行会把计划文件写坏**：提交时返回 `ok:true`，之后 `status` 永久报「读不懂」。现在标题、文件路径一律拒绝换行，与验收标准同等对待。
- **文件路径里的逗号会被拆开**：`src/a,b.js` 曾读回成两个文件。计划文件改成**一个文件一行、一个依赖一行**，不再依赖分隔符；实机用 `src/a,b.js` 验证过原样读回。
- **`EVIDENCE_TYPES` 有两份拷贝**（工具 schema 一份、校验一份），漂移会导致「广告的能填、填了却被拒」。改为从状态机模块导出，index 引入。
- **图分析重复建表**：原来三次各建一张 `Map`。现在只在存在文件集重叠时才按需计算祖先集合，并对每个部分做记忆化。
- **读取时重新校验**：`plan.md` 被手改成不合法内容时，`status` 报错而不是给出残缺计划。
- **测试脚手架重复**：`memoryStore` 抽到 `test/memory-store.js`。
- **术语**：glossary 补一句说明 `dsh-manager` / `/manager` 是产品名，「主对话」才是概念的称呼；工具描述里不再用 glossary 列为 _Avoid_ 的「证明」。
